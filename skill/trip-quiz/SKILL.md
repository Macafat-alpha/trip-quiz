# trip-quiz（旅クイズを作る）

遊ぶアプリ: https://macafat-alpha.github.io/trip-quiz/
このファイルと同じフォルダの `scripts/` に、取得スクリプトと検証スクリプトがある。以下の `<SKILL_DIR>` は、このskillのベースディレクトリに置き換えて実行する。

## 絶対に守ること

- **問題文・選択肢・正解・解説・引用をチャットに出さない。** 作る人も回答者。報告は件数・内訳・検証結果だけ
- 録音のタイトルも出さない（内容のネタバレになる）

## 手順

1. **聞く**（足りないものだけ、1回にまとめて聞く）
   - 参加者の名前と読み（ひらがな）。例: 「花子＝はなこ、翔＝しょう」。読み上げで名前を正しく読ませるために使う
   - 日付（既定は今日）と、その日の場面の流れ（例: 行きの車／BBQ／温泉／夕食）。場面は時間帯の見出しに使う
   - 素材の場所: 文字起こしのテキストファイル（どの録音アプリでもよい）の場所か、Plaud を使ったか
2. **素材を用意する**
   - **テキストの場合（基本）**: 指定されたファイル（.txt / .md など。iPhoneのボイスメモ、Googleレコーダー、Notta など、どの録音・文字起こしアプリの書き出しでもよい）をそのまま読む。複数あれば全部読む
   - **Plaud の場合（任意）**: `plaud me` でログイン状態を確認し、`python3 <SKILL_DIR>/scripts/fetch_plaud.py YYYY-MM-DD [--from HH:MM]` を実行する
     - 出力は `./trip-quiz/work/YYYY-MM-DD/day.txt`（`[HH:MM] Speaker N: 発話`、日本時間）
     - 旅と関係ない録音（仕事など）が混ざる日は `--from` で出発時刻以降に絞る
     - 文字起こしが空の録音があれば、Plaud アプリで録音ごとに「文字起こし」を実行してから再実行してもらう（同期だけでは文字起こしは始まらない）
     - `plaud` コマンドがなければ `npm i -g @plaud-ai/cli` → `plaud login` を案内する
3. **読む**: 素材を全部読む。時刻がない素材は、場面の流れから segment を決める
4. **作る**: 下の「問題の作り方」に従って `./trip-quiz/quiz-YYYYMMDD.json` を書く
5. **検証**: `python3 <SKILL_DIR>/scripts/validate_quiz.py ./trip-quiz/quiz-YYYYMMDD.json --min 15`
   - NG があれば直して再検証。出力は件数とIDだけなので、そのまま報告してよい
6. **渡す**（3つの方法を示す）
   - Mac で `pbcopy < ./trip-quiz/quiz-YYYYMMDD.json` → 同じApple IDのiPhoneでアプリの「JSONを貼り付ける」に貼る（ユニバーサルクリップボード）
   - AirDrop・LINE・メールでファイルを司会のスマホに送り、アプリの「クイズファイルを選ぶ」で選ぶ
   - iCloud Drive などに置いて、スマホの「ファイル」アプリから選ぶ
7. **報告**: 問題数、形式・種類・難易度・時間帯の内訳、きわどい問題の数、検証結果、アプリのURL

## クイズファイル（スキーマv1）

```json
{
  "version": 1,
  "title": "〇〇旅行 クイズ",
  "date": "2026-09-27",
  "players": [
    { "name": "たろう", "reading": "たろう" },
    { "name": "花子", "reading": "はなこ" }
  ],
  "questions": [
    {
      "id": "q01", "type": "choice", "segment": "BBQ", "difficulty": "easy",
      "vibe": "kudaranai", "spicy": false,
      "question": "BBQで最初に網に乗せたのは？",
      "speech": "バーベキューで、最初に網に乗せたのは？",
      "choices": ["牛カルビ", "ソーセージ", "玉ねぎ", "とうもろこし"],
      "answer": "ソーセージ",
      "explanation": "開始直後に「まずソーセージからでしょ」。",
      "evidence": { "quote": "まずソーセージからでしょ", "time": "12:20頃", "source": "plaud:<file_id>" },
      "confidence": "high"
    }
  ]
}
```

| type | 必須 | 補足 |
|---|---|---|
| `choice` | `choices`(2〜4) `answer`(choicesのどれか) | `choices_speech` 任意（選択肢の読み）。正解が複数なら `answer` を配列に |
| `who` | `answer`(playersのname) | `choices` は省略＝全員。複数人が正解なら `answer` を配列に |
| `truefalse` | `answer`(true/false) | |
| `number` | `answer`(数値) | `unit` 任意。一番近い人が正解 |
| `open` | `answer`(模範解答) | 司会が判定。別解があれば配列に |

- `points` は省略（easy/normal=1、hard=2 をアプリが付ける）。ラスト3問の2倍もアプリ側
- `difficulty`: easy / normal / hard。**易→難の順に並べる**
- `vibe`: kudaranai / omoshiroi / sasai、`spicy`: 真偽値、`confidence`: high / low

## 問題の作り方

- **20問**（素材が少なければ15問まで下げてよい。減らすときは各形式を同じ比率で減らす）
- 配分の目安
  - vibe: くだらない4割・面白い4割・些細すぎて誰も覚えていない2割
  - difficulty: 易しい2割・ふつう3割・難しい5割
  - type: choice 7〜8／who 5／truefalse 3／number 2／open 2（参加者が2人なら who は2〜3問に減らす）
  - segment: 場面ごとに偏らせない
- **segment は場面単位**で付ける（録音単位ではない）。名前は場面名だけを使う（中身を表す名前にしない。報告で内訳を出すため）
- **難しい問題**: 細かい数字（番号・人数・時刻・金額）、本人も忘れていそうな一言の穴埋め、似た選択肢が並ぶ4択、ひっかけ（複数人が言っていた・全部当てはまる）。ただし文字起こしで正解を確かめられるものだけ
- **正解が複数**: 同じことを複数人が言った・した場合は who の `answer` を配列にする。choice で複数正解にするときは問題文に「すべて選んで」と書く
- **話題**: 参加者に聞いて決める。指定がなければ除外しない。きわどいものは `spicy: true`（アプリで出す／飛ばすを切り替えられる）
- **読み上げ前提で書く**
  - 問題文は1〜2文、40字前後まで。耳で聞いて一度で分かる語順
  - 読みが怪しい語は `speech` に読みやすい表記を入れる（BBQ→バーベキュー）。選択肢は `choices_speech`
  - 人名は players の name をそのまま書く（アプリが読みに置き換える）
- **選択肢**はどれもありそうに見せる。「全部」「どれでもない」は使わない。別の場面で正解になりうる語は誤答に使わない
- **○×**: ○と×を混ぜる。否定文（「〜しなかった」）は耳で聞くと混乱するので肯定文で書く
- **who（誰が言った？／誰がした？）**
  - Plaud の話者番号は録音ごとに振り直され、声紋で付く実名ラベルも誤りが多い。呼びかけ・自称・直後の返答・その人しか知らない事情から特定する
  - 根拠が弱いものは `confidence: "low"`（アプリは出題しない）。迷ったら low
- **証拠** `evidence.quote` は30字以内で原文から。明らかな誤転写は意味が変わらない範囲で直してよい
- 文字起こしが崩れて意味が取れない箇所、確かめられない数字は問題にしない
- 解説 `explanation` は1〜2文。答え合わせで読み上げるので、オチを一言で
